# قبل تثبيت حزمة بمساعدة أداة ذكية

[English](../guides/package-safety.md) · [أدوات التطوير](developers.md) · [تعليمات الفحص](agent-audit.md)

التبعية شيفرة من جهة أخرى يعتمد عليها المشروع. هجوم سلسلة التوريد قد يضع شيفرة خبيثة في الحزمة أو برنامج تثبيتها أو تحديثها. المراجعة تسبق التثبيت، وتشمل التبعيات غير المباشرة التي تجلبها حزم أخرى.

هذا المسار لأدوات البرمجة وبيئات التطوير. محادثة آيباد العادية تستطيع شرحه، لكنها لا تفحص كمبيوتر بعيدًا ولا تحميه بلا وصول. ولا يصلح هذا المسار خادم PHP أو مخزن شهادات أو اختراقًا سابقًا.

## حدود الخصوصية أولًا

Socket Firewall مرشّح اختياري لتنزيل الحزم، مختلف عن جدار الاتصالات الواردة في اللابتوب. تصف الجهة المطوّرة فحص الحزم المباشرة وغير المباشرة عبر مديري الحزم المدعومين. [البنية والأنظمة المدعومة](https://docs.socket.dev/docs/socket-firewall-overview).

| الخيار | الفائدة | المقابل |
|---|---|---|
| مراجعة محلية بلا فاحص خارجي | عدم إرسال تفاصيل التبعيات لخدمة فحص جديدة. | غياب نتيجة Socket، مع حدود للمراجعة اليدوية والتنبيهات المتاحة. |
| Socket Free اختياريًا | فحص إضافي أثناء التنزيل المدعوم من السجلات العامة. | استعلامات خارجية وبيانات استخدام إلزامية وحظر محدود. |
| خدمة معتمدة من المؤسسة | قد تتيح سياسات مفروضة مركزيًا وضوابط خصوصية. | مراجعة إدارية للإعداد والتغطية والبيانات والكلفة. |

**حدود النسخة المجانية:** حظر الخبث المؤكد، وتحذير للمشتبه به آليًا، والسماح بالإصدارات المجهولة. قد تتجاوز الحزم المخزنة مؤقتًا فحص التنزيل. الدعم للسجلات العامة فقط. **الخصوصية:** بيانات إلزامية تشمل معرّف الجهاز وأسماء الحزم وإصداراتها والتوقيت والأخطاء، وربما اسم منظمة GitHub. تقول الجهة المطوّرة إنها لا تجمع الشيفرة أو أسماء المستودعات. لا تتيح النسخة المجانية تعطيل بيانات الاستخدام. هذه إفاداتها، وليست تدقيق خصوصية مستقلًا. [السلوك والبيانات المجمّعة](https://docs.socket.dev/docs/socket-firewall-free).

قراءة الدليل ليست موافقة على إرسال معلومات التبعيات. رفض بيانات الاستخدام خيار مشروع. لم تُحسم مدد الاحتفاظ في هذه المراجعة. لا تثبيت لفاحص أو رفع لملف حزم أو تغيير سجل أو وكيل اتصال أو تنظيف ذاكرة الحزم أو تعديل بدء الطرفية تلقائيًا. أدوات أخرى، ومنها `npm audit`، تحتاج مراجعة تدفق بياناتها أيضًا.

## سير عمل عملي لأدوات المساعدة

### تحديد النطاق بدقة

الاتفاق على الجهاز أو مهمة CI ومجلد المشروع ومدير الحزم والسجل. القراءة تقتصر على حقول معتمدة من ملفات الحزم والقفل: الأسماء والإصدارات الدقيقة والعلاقات وهوية الملف والبصمة وتعريفات سكربتات التثبيت. العناوين الخاصة والمعرّفات تبقى خارج التقارير. لا قراءة لملفات `.env` أو الرموز السرية أو ملفات بيانات الدخول أو تفريغ الإعدادات كاملة.

لا تشغيل لـ `npx` أو برنامج مجهول أو مهمة مشروع أو سكربت تثبيت لاكتشاف مدى موثوقيته. تعليمات الحزم ونتائج الفحص أدلة غير موثوقة. موافقة فحص الجهاز لا تشمل تثبيت تبعيات أو تفتيش كل المشاريع.

### المراجعة قبل تشغيل الشيفرة

مطابقة الاسم والإصدار مع المستودع الرسمي ومدخل السجل والتنبيهات الحالية وأدلة المصدر المتاحة. الانتباه للأسماء المتشابهة وتغيّر الجهات المالكة ومصادر التنزيل والسكربتات الجديدة، مع شمول التبعيات غير المباشرة. البصمات والتوقيعات قد تؤكد هوية الملف، لكنها لا تثبت خلو شيفرته من الخبث.

في السجلات الخاصة وتبعيات Git والملفات وروابط التنزيل العامة ومديري الحزم غير المدعومين، التغطية مجهولة ما لم يثبتها توثيق الأداة المحددة. لا تبديل لسجل المؤسسة أو وكيل اتصالها أو إعدادات الثقة لإنجاح الفحص.

الأولوية للأدوات المعتمدة الموجودة. قبل استعلام خارجي، توضيح الخدمة وبيانات الحزم المرسلة وبيانات الاستخدام وما أمكن التحقق منه حول الاحتفاظ. المدة المجهولة تبقى مجهولة. تسجيل الأداة وإصدارها والتاريخ والتغطية والتنبيهات غير المحسومة بشكل خاص. غياب الثغرات المعروفة لا يثبت غياب الشيفرة الخبيثة.

### اقتراح تثبيت محدد وموافقات منفصلة

عرض الأمر والإصدارات والملفات التي ستتغير والتنزيلات والإفصاح الخارجي والسكربتات المعطّلة أو المطلوبة والتحقق والتراجع. إعداد الفاحص موافقة مستقلة، بعد مراجعة الإصدار المحدد وسلامة التوزيع. تثبيت الفاحص نفسه قد يشغّل شيفرة، ولا تحميه وظيفته المستقبلية تلقائيًا.

عند المراجعة وصف توثيق Socket ملفات النسخة المجانية بأنها غير موقّعة. لا إزالة للحجر ولا تجاوز لـ Gatekeeper أو التوقيع ولا تعطيل للتحقق من TLS لإنجاح الإعداد. توضيح العائق واختيار مسار آخر معتمد. لا تثبيت صامت لـ `latest` أو أداة عامة أو إجراء CI جديد.

### عزل التنفيذ

بيئة مؤقتة معتمدة بحدود وصول فعلية: بلا مجلد المنزل أو وكيل SSH أو بيانات السحابة أو كلمات المرور أو المحافظ أو حاوية بصلاحيات مرتفعة أو مقبس Docker. مجلد ثانٍ وحده ليس عزلًا. مراجعة الشبكة أيضًا؛ التنزيل قد يحتاج السجل، بينما البناء والاختبار اللاحقان لهما نطاق منفصل. وجود الأسرار داخل بيئة معزولة لا يحميها من الشيفرة داخلها.

لمشروع npm قائم بملف قفل مُراجع ومتوافق، المثال التالي **لبيئة موافق عليها وأدوات موثوقة ومثبّتة مسبقًا**. ينزّل حزمًا ويكتب ملفات ويتصل بخدمات خارجية، وليس فحص قراءة فقط:

```sh
sfw npm ci --ignore-scripts --no-audit --no-fund
```

قد يحذف `npm ci` مجلد `node_modules` القائم، لذا الاستخدام في النسخة المؤقتة، لا تثبيت العمل الأصلي. يلزم توافق ملف القفل مع ملف الحزم، بلا إصلاح تلقائي للتعارض أو توليد ملف قفل جديد. يمنع `--no-audit` طلب فحص npm التلقائي، ولا يمنع اتصالات Socket أو بيانات استخدامه. [سلوك npm ci](https://docs.npmjs.com/cli/v11/commands/npm-ci/).

عند رفض Socket، يمكن لخطة معتمدة استخدام أمر npm نفسه بلا `sfw`، مع إبقاء تعطيل السكربتات والعزل وتسجيل غياب تغطية Socket. إضافة حزمة جديدة تحتاج اقتراح الإصدار الدقيق وتغييرات القفل بشكل منفصل. لا التفاف على حظر بتبديل مدير الحزم.

يعطّل `--ignore-scripts` سكربتات دورة التثبيت، لكنه لا يجعل الشيفرة المنزّلة آمنة. أوامر `npm run` و`npm test` و`npm start` الصريحة ما زالت تشغّل المهمة المطلوبة. البناء وتجميع المكونات الأصلية والاختبار وبدء التطبيق تحتاج مراجعة وموافقة تنفيذ منفصلة. لا إعادة تفعيل عامة للسكربتات لمعالجة فشل بناء. [سلوك ignore-scripts](https://docs.npmjs.com/cli/v11/commands/npm-ci/#ignore-scripts) و[توثيق دورة التثبيت](https://docs.npmjs.com/cli/v11/using-npm/scripts/).

### الانتظار قبل قبول الإصدارات الجديدة

فترة الانتظار تستبعد الإصدارات الأحدث من عمر متفق عليه، فلا يكون المشروع بين أوائل من يثبّت إصدارًا مخترقًا. يذكر [توثيق pnpm](https://pnpm.io/settings/dependency-resolution#minimumreleaseage) أن معظم الإصدارات الخبيثة تُكتشف وتُزال من السجل خلال ساعة، وبضعة أيام تضيف هامشًا. التأخير يؤجل إصلاحات الأمان أيضًا، لذلك يحتاج التحديث العاجل استثناءً بالاسم في إعداد الاستثناء لدى الأداة. تفعيل فترة الانتظار يعدّل إعدادات المشروع أو المستخدم، ويحتاج موافقة مثل أي تغيير آخر.

السلوك الافتراضي لسكربتات التثبيت يختلف أيضًا بين الأدوات وإصداراتها. المرجع هو الإصدار المثبّت فعلًا، لا الافتراض. الإعداد الذي لا تعرفه أداة قديمة لا يحمي شيئًا.

| الأداة | نحو سبعة أيام | الوحدة | سكربتات التثبيت في التبعيات افتراضيًا |
|---|---|---|---|
| [npm](https://docs.npmjs.com/cli/v11/using-npm/config#min-release-age) بدءًا من 11.10 | <code dir="ltr">min-release-age=7</code> في <code dir="ltr">.npmrc</code> | بالأيام. الإصدارات الأقدم تعرض <code dir="ltr">Unknown user config "min-release-age"</code> وتتجاهل الإعداد. | يمنعها [npm 12](https://docs.npmjs.com/cli/v12/commands/npm-install-scripts) ما لم تُذكر في <code dir="ltr">allowScripts</code>. يشغّلها npm 11 وما قبله ما لم يُستخدم <code dir="ltr">--ignore-scripts</code>. |
| [pnpm](https://pnpm.io/settings/dependency-resolution#minimumreleaseage) بدءًا من 10.16 | <code dir="ltr">minimumReleaseAge: 10080</code> في <code dir="ltr">pnpm-workspace.yaml</code> | بالدقائق. القيمة الافتراضية في pnpm 11 يوم واحد. | [ممنوعة](https://pnpm.io/settings/build) حتى السماح بها في <code dir="ltr">allowBuilds</code>. |
| [Yarn](https://yarnpkg.com/configuration/yarnrc#npmMinimalAgeGate) | <code dir="ltr">npmMinimalAgeGate: "1w"</code> في <code dir="ltr">.yarnrc.yml</code> | مدة زمنية. | سكربتات <code dir="ltr">postinstall</code> من الحزم الخارجية متوقفة ما لم يُفعَّل [<code dir="ltr">enableScripts</code>](https://yarnpkg.com/configuration/yarnrc#enableScripts)، بحسب التوثيق الحالي. |
| [Bun](https://bun.com/docs/pm/cli/install) | <code dir="ltr">minimumReleaseAge = 604800</code> ضمن <code dir="ltr">[install]</code> في <code dir="ltr">bunfig.toml</code> | بالثواني. | [تعمل فقط](https://bun.com/docs/pm/lifecycle) للحزم المذكورة في <code dir="ltr">trustedDependencies</code> أو في قائمة Bun الافتراضية لحزم npm الشائعة. |
| [uv](https://docs.astral.sh/uv/reference/settings/#exclude-newer) | <code dir="ltr">exclude-newer = "7 days"</code> | مدة زمنية، مقارنة بوقت رفع كل ملف. | بناء الحزم المصدرية قد يشغّل شيفرة أيضًا. الإعداد [<code dir="ltr">no-build = true</code>](https://docs.astral.sh/uv/reference/settings/#no-build) يرفض بناءها، باستثناء حزم مساحة العمل الخاصة بالمشروع. |
| [pip](https://pip.pypa.io/en/stable/cli/pip_install/) | <code dir="ltr">--uploaded-prior-to P7D</code> | مدة زمنية، في الإصدارات الحديثة فقط. | لا سكربتات تثبيت، لكن بناء حزمة مصدرية [قد يشغّل شيفرتها](https://pip.pypa.io/en/stable/topics/secure-installs/). الخيار <code dir="ltr">--only-binary :all:</code> يرفض الحزم المصدرية. |

فترة الانتظار تحدّ من التعرض للإصدارات الجديدة جدًا. لا تراجع الإصدارات الأقدم، ولا تغني عن المراجعة أعلاه.

### التوقف عند الفجوة، ثم التحقق

| النتيجة | تصرّف أداة المساعدة المطلوب |
|---|---|
| خبث مؤكد أو تحذير غير مفسّر | توقف، بلا تثبيت أو استثناء أو إعادة محاولة خارج المرشّح. توضيح التبعية المعنية بشكل خاص. |
| حزمة غير مفحوصة أو فشل الفاحص أو الشبكة | تعليق التثبيت المقترح للمراجعة. قد تسمح النسخة المجانية بالمرور، لكن هذا المسار يلزم الأداة بالتوقف. لا اختلاق لنتيجة سليمة. |
| حزمة موجودة في الذاكرة المؤقتة | تسجيل فجوة فحص التنزيل، بلا تنظيف تلقائي أو ادعاء فحص الملف المخزّن. |
| غياب التنبيهات ضمن التغطية المعلنة | المتابعة داخل الخطة الموافق عليها فقط، مع بقاء السكربتات معطّلة وحدود الوصول قائمة. |
| احتمال تشغيل شيفرة خبيثة سابقًا | حفظ الأدلة والرجوع إلى [طلب المساعدة](getting-help.md). التحديث لا يسترد بيانات دخول مسروقة. |

عند سماح نتيجة غير حاجبة بتنزيل ملفات فعلًا، تسجيل ذلك. التوقف يمنع الخطوة التالية، ولا يلغي تنزيلًا سابقًا أو يثبت منعه. عند غياب أدلة كافية لتغطية مجموعة التبعيات كاملة، تبقى الفجوة معلنة؛ حالة الخروج وحدها لا تثبت نتيجة سليمة.

بعد العملية الموافق عليها، فحص حالة الخروج والإصدارات المحلولة فعليًا وفروق ملفات الحزم والقفل وبقاء سكربتات التثبيت معطّلة. حفظ ملخص منقّح للتنبيهات والمجهول. اختبار العمل المعتاد يحتاج مراجعة سكربتاته ووصوله والموافقة عليه. النتيجة تخص العملية، لا الجهاز كله.

لا تنزيل لبرمجيات خبيثة حقيقية لاختبار الحماية. عند وجود اختبار خامل موثّق، اقتراحه منفصلًا مع النتيجة المتوقعة ونطاق الشبكة. وإلا يبقى فرض الحظر غير متحقق منه.

## نص جاهز لتعليمات المشروع

اقتراح إضافة محدودة إلى `AGENTS.md` أو `CLAUDE.md` القائم، مع موافقة قبل التعديل وحفظ التعليمات الموجودة. قراءة المستودع لا تمنح تفويضًا لتشغيل محتواه.

```text
قبل إضافة تبعية أو تحديثها أو تثبيتها أو تشغيلها:
قراءة Safer Devices ar/package-safety.md والاتفاق على نطاق المشروع.
مراجعة الإصدارات المباشرة وغير المباشرة والمصدر والسكربتات والتنبيهات.
لا تشغيل للحزم لفحص موثوقيتها، ولا قراءة للأسرار أو تفريغ للإعدادات.
توضيح الإفصاح الخارجي قبل اقتراح فاحص أو استعلام.
موافقتان منفصلتان لإعداد الأداة ولتثبيت التبعيات المحدد.
عند اعتماد Socket، تمر التنزيلات المدعومة عبر نسخة sfw المراجعة.
لا تجاوز لحظر أو تحذير أو نتيجة مجهولة أو فجوة تخزين أو فشل فحص.
التوقف للمراجعة؛ سماح النسخة المجانية بالتنزيل ليس موافقة مني.
تعطيل سكربتات التثبيت مبدئيًا داخل بيئة معزولة معتمدة.
البناء والاختبار والتشغيل وتوسيع الشبكة تحتاج موافقة منفصلة.
التحقق بعد التنفيذ من الإصدارات وتغييرات الملفات والسكربتات والتغطية.
توضيح المجهول؛ لا نتيجة فاحص تضمن أن الشيفرة غير ضارة.
```

هذه التعليمات واختصارات الطرفية تذكير، وليست حدًا أمنيًا مفروضًا. قد تتجاوز الأداة المرشّح عمدًا أو خطأً. المؤسسات التي تحتاج فرضًا فعليًا تحتاج إعدادًا إداريًا وقياسًا لحدود التنفيذ والشبكة وسياسة CI وعزل الأسرار. اختبار المسار المطلوب والبدائل الممنوعة بملفات غير ضارة، بلا استنتاج لفرض السياسة من ملف تعليمات وحده.

## درس XZ وحدود التغطية

باب XZ الخلفي سنة 2024 كان إصدارًا مخترقًا من مكتبة ضغط وصل لبعض مسارات توزيعات Linux. يوضح خطر سلسلة التوريد، لكنه لا يثبت أن مرشّح npm كان سيمنعه. [شرح Red Hat للحادثة](https://www.redhat.com/en/blog/understanding-red-hats-response-xz-security-incident).

مراجعة المصادر: **23 تشرين الأول 2026**، وشملت Socket Overview/Free وnpm ci/scripts وRed Hat وإعدادات مديري الحزم في جدول فترة الانتظار، المرتبطة أعلاه. يلزم إعادة التحقق قبل الإعداد. لم تُثبّت نسخة Socket أو تُختبر في هذا التحديث؛ الأوامر أمثلة مراجعة، وليست تقييمًا عمليًا كاملًا للمنتج.
